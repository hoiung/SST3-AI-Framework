## Procedure

The draft exists. Now verify it is correct before it becomes the contract.

**Process**:
1. Read the `/tmp` issue draft from Stage 2. Read `graph_applicable` from the Stage 1 research file — do NOT re-classify independently (TB-2 single-declaration-carries-forward). **Binary grep gate (AC 3.5 + AC 7.2):** `grep -c '## Triple-Check Gate' /tmp/issue_draft*.md` and `grep -c '## Solo Assignment (SST3 Automated)' /tmp/issue_draft*.md` — either count == 0 → BLOCK issue creation. **ALSO** `/usr/bin/grep -c '## Chat Reconciliation' /tmp/issue_draft*.md` must be `>= 1` (the verifier-led reconciliation report from step 2a cannot be silently skipped) — `== 0` → BLOCK issue creation. **Volatile-state re-probe (#555 Phase 4):** re-probe any volatile environment claim carried from Stage 1 (git worktree list, running processes, live-DB reads — incl. every AC tagged `[provisional: live-probe]` from Stage-2 sub-check (q)) rather than inheriting the Stage-1 snapshot; for a 'leave as legacy' deferral, verify the artifact's last-modified date against the voice cutoff before accepting it.
2. Author + run the sanity-check swarm via the Workflow tool (DEFAULT; minimum 3 subtasks, scale up; Agent/Task = the documented fallback only for a trivial single-angle check). **Multi-skill dispatch (AP #23)**: when invoked-skill canonical token cost exceeds ~5K (e.g. 3+ skills × deep canonicals), split the skill-canonical compliance angle into multiple subagents — one per canonical file — so each comprehensive-walk stays within its context budget. This is orchestrator-side guidance for the Leader; the per-subagent template (what each subagent receives verbatim) lives in STANDARDS.md "Skill-Canonical Audit Template (Comprehensive Walk)". **Dispatch preamble (AC 3.13):** attach the parked Stage-2 feedback file (or its Stage-2 section from `SST3-metrics/leader-feedback/feedback-<repo>-<issue>.md`) to the subagent scope snippet so subagents enter Stage-3 knowing what Stage-2 already resolved — do NOT re-raise findings Stage-2 already closed. Each verifies independently: **Stage-merge declaration (#555 Phase 4):** for small single-objective issues merging the Stage-2 and Stage-3 swarms into one dispatch, record `stage_merge: [2+3]: <justification>` + the combined angle list in the research/scope file — same discipline as the angle-level `L2-merge` declaration; an unrecorded merge reads as a dropped stage at audit.
   - **Scope vs Audit**: 100% of research findings captured? Nothing missing? No gaps? **Counter-Scoping angle (#555 Phase 4 — mandatory, distinct from this under-coverage check):** does any AC promise MORE than the design/research supports, or narrow what it delivers? Flag BOTH directions; a research-derived 'implied' obligation touching an EXISTING surface the operator never named is flagged `invented` at draft time, not deferred to downstream reconciliation.
   - **No overengineering**: Scoped items that solve problems that don't exist? Remove them.
   - **Named-scope fidelity (AC 3.2)**: does any AC apply to a BROADER set than the operator literally named in the research restatement / `## Agreements Log`? Flag any superset (e.g. a named `MB100/MBS100` set silently widened to "all strategies" / "uniform"). The enumeration IS the scope — see STANDARDS.md "Named-Entity Scope — Don't Broaden a Named Set".
   - _(The former "Chat history check" + "Opposite-scoping check" subagent bullets are REMOVED — they were structurally vacuous because subagents never receive the conversation. They are replaced by the MAIN-AGENT-owned verifier-led step 2a below.)_
   - **Negative-polarity sweep (AC 5.6)**: for any AC that changes a config value, contractual term, or narrative framing, grep the full doc tree for the SUPERSEDED token (old value / old issue-number / old wording) and assert zero unexpected hits outside intentional historical comment blocks. A recalibration that updates the one site you noticed but leaves the old value load-bearing elsewhere is the AP #9 single-source failure. **Pin the binary (#555 Phase 4):** every grep in this sweep — and ANY filter/exclusion chain whose output feeds a pass/fail decision — uses `/usr/bin/grep` explicitly (the interactive ugrep alias emits nothing in a pipe: a silent false-CLEAN; STANDARDS.md pinned-grep rule). Script-internal greps in `../../scripts/*.sh` run non-interactive shells and are not exposed to the alias.
   - **Producer-surface enumeration (AP #30 — dotfiles#528 AC 6.1)**: for any AC that changes a value crossing a process/serialisation boundary (HTTP body, websocket/SSE frame, cache key/field, DB column, emitted log/metric), enumerate EVERY producer of that value by CONCEPT ("what else emits this fact?") — NOT by shared token — and confirm each paired emit-surface is in scope or deliberately exempt. A token-blind producer pair (e.g. an SSE push beside a Redis `HSET`) escapes both the AP #24 literal-marker grep and the AP #14e pattern-class sweep; this is the manual angle that catches it. Skip-clean if the issue changes no cross-boundary value. See ANTI-PATTERNS.md AP #30.
   - **Dead/obsolete/legacy code**: Did the audit find cleanup targets? Are they in the issue? Structural layer: `bash $SST3/sst3-code-large.sh 200 <lang>` + `bash $SST3/sst3-code-impact.sh <base-branch>` on the area the Issue edits, when graph available and fresh (pre-query gate per STANDARDS.md "Structural Code Queries"). Surfaces dead-code / wide-blast-radius candidates that should be in scope. Subagent still verifies intent (intentional duplication vs accidental). **Raw-tool counter-query (#447 Phase 5 — Stage 3 sanity check)**: for any structural scope item the wrapper-lane surfaced (callers count, large-fn list, dead-code candidates, blast-radius), dispatch ONE subagent to run the equivalent raw tool (grep / ast-grep direct / find) on the same target. Compute delta. **Delta >50% wrapper/raw discrepancy = BLOCK Issue creation** until reconciled — either the wrapper missed instances (recall drift, file a separate fix Issue first) or the raw tool double-counted (false positive in raw, document and proceed). Record the counter-query + delta + reconciliation in the draft's References section.
   - **All scope in issue BODY**: Nothing in comments. Everything in the body.
   - **Skill-canonical compliance** (Double-Guardrail Principle — N32): subagent uses the comprehensive-walk template per STANDARDS.md "Skill-Canonical Audit Template (Comprehensive Walk)". Reads the invoked-skill canonical file(s) per Stage 1 metadata `invoked_skill` + `skill_canonical_files`, walks EVERY `## ` and `### ` heading, returns per-section [PASS|FAIL|N/A] with file:line evidence tagged by `source_file`. RESULT block extends with `canonicals_walked` + `section_failures` + `fallback_applied`. Do NOT pre-filter by which rules "look relevant". See ANTI-PATTERNS.md AP #23 for the curator-bounded-recall failure mode this template prevents. **Twist sub-prompt (#484 V2.3)**: when `invoked_skill ∈ {blog, voice-doc-repo}` AND the draft contains AI-integrated operator-supplied prose, the comprehensive-walk MUST additionally run the STANDARDS.md "Polish vs Twist (Semantic Frame Preservation)" TWIST-forbidden checklist against each polished hunk vs its operator-supplied source (qualifier-add / comparison→verdict e.g. `costs vs value`→`costs outweigh value` / hedge-drop / imposed analytical lens), returning per-hunk PASS/FAIL — the semantic-frame half of skill-canonical compliance the heading-walk alone cannot catch (AP #25; subagent-only, no programmatic detector possible).
   - **Mirror-lane mapping completeness** (#460 Phase 8 W5 — AP #9): subagent verifies that any draft AC touching CLAUDE.md or SST3-canonical code includes its "Mirror Lanes Traversed" subsection (per Stage 2 step 4a) AND that the propagation tooling (`propagate-template.py` for Lane A, `propagate-mirrors.py` for Lane B) is named explicitly in the AC's verification step. Drafts that edit canonical-mirrored surfaces without naming the lane fail this angle.
   - **Verify-command execution (AC 3.1)**: EXECUTE every AC verify command against live source; report PASS/FAIL per command; flag tautological verifiers — ones an implementer could satisfy while the defect still ships. **Fixture execution + scope guard (#555 Phase 3):** execute each verify command against (1) the PRE-FIX tree (the existing check), (2) a mocked POST-FIX snippet, (3) for any `grep -E` alternation, a 1-line POSITIVE fixture that MUST match, and (4) for find/replace ACs, a simulated `str.replace()` diffed verbatim — a verify that was never seen matching anything can be vacuous in ways the pre-fix dry-run misses. Scope guard: SKIP long-running regression suites inline — label them `runtime-gate-not-executable-now` — never launch them mid-audit. **Verdict tagging (#555 Phase 4):** a verify failing because the target artifact does not yet exist is tagged `target-state-absent (expected)` — reserve `draft-defect (must fix before filing)` for genuine authoring errors; conflating the two produces false BLOCK verdicts on a pre-implementation tree.
   - **Behaviour-change caller sweep (#555 Phase 3)**: for any AC changing a function's signature / behaviour / return-contract, run `bash $SST3/sst3-code-callers.sh <fn> <lang>` (grep fallback), enumerate EVERY call site, confirm each is compatible with the new behaviour, and record PASS/FAIL per caller — a generic "any other caller?" Layer-1/2 prompt is not sufficient.
   - **Architecture-replacement collision sweep (#555 Phase 3)**: when an AC removes/replaces an existing mechanism wholesale, dispatch a whole-system integration/collision/dead-code sweep angle BY DEFAULT — never gate it behind an operator prompt.
   - **Expected Behavior ↔ AC internal consistency (AC 3.3)**: for every bullet in Expected Behavior, identify the AC that would fail if the behavior is absent; flag any EB bullet with no AC binding. **Deferred-Feature Prose Coherence (AC 3.3)**: grep the draft for every symbol/function/feature name appearing in any DECISION CALLOUT deferral block; confirm every occurrence outside that block is intentional and documented.
   - **AC checkbox walk (AC 3.5 L1-A)**: walk every ``^- \[ \] \*\*AC`` checkbox sequentially, report the count, and compare against the Stage-2-declared count in the Triple-Check Gate.
   - **Filesystem-state verification (AC 3.7)**: walk every "X exists / X does not exist / X is at path Y / X has properties Z" claim in the draft; run `ls` / `find` / `git ls-tree <branch> <path>` / `grep -rln` against the actual repo at audit time; report PASS/FAIL per claim. For relocation issues, grep the ENTIRE `vendored_files` set for the moved path literal (not just draft-named files). For drift-manifest consumers, check `git ls-tree` on every relevant non-main branch for false-absent path claims. For operator-facing manual procedures, include a hardware-prerequisite sweep (what physical tools/keys/programmers must be on hand before each phase). **File-nature claims (#555 Phase 4):** for 'X is a regular file / symlink / copy of Y' premises, run `readlink -f` + `ls -di` on BOTH sides (inode identity) — an `ls -l` glance is not proof.
   - **Citation verification (AC 3.4 — conditional, >5 source line refs)**: one subagent exclusively grep-verifies each cited file:line; pass/fail per ref, no analysis.
2a. **Chat Reconciliation (Verifier-Led) — MAIN-AGENT-OWNED, non-delegable (AC 7.1).** This replaces the old subagent "Chat history" + "Opposite-scoping" bullets, which were structurally vacuous (subagents never receive the conversation). Extract the operator's raw typed messages with `python3 $SST3/extract-chat-agreements.py --issue <N>` and read the research file's `## Agreements Log`. Dispatch a THREE-MODEL neutral verifier panel — one Haiku + one Sonnet + one Opus, IN PARALLEL via the Workflow tool's per-agent `model` override (model diversity = different blind spots; distinct from Ralph's SEQUENTIAL code-review) — each given ONLY those raw messages + the agreements log and the NEUTRAL prompt — they are NOT shown the issue/scope/diff (so they cannot be led into rubber-stamping): "From these messages, what did the operator ask for / agree to / rule out? Cite each to a message; do NOT speculate beyond what is stated." The MAIN AGENT then double-checks each independent interpretation against (a) its own understanding and (b) the drafted issue scope — divergence is the drift signal: in-issue-not-in-interpretation = `invented`; in-interpretation-not-in-issue = `dropped`; contradicts = `inverted`. POST the consolidated report (per-model reads + the `{invented, dropped, inverted}` divergence) as a `## Chat Reconciliation` section in the issue draft body, then PAUSE for explicit operator approval of that report BEFORE creating the issue (step 6). Honest limit: the binary gate (AC 7.2) only guarantees the report is PRESENT; the panel + operator catch truthfulness. Full doctrine + template: STANDARDS.md "Chat Reconciliation (Verifier-Led)". **Scope gate (#555 Phase 3):** for a proven, operator-agreed SMALL tail — no contested interpretation, an explicit prior agreement cited verbatim — a main-agent-only reconciliation note is sufficient: skip the 3-model panel and record the citation in the `## Chat Reconciliation` section instead. Reserve the mandatory panel for scope where the operator's intent is genuinely contested or ambiguous — model diversity earns its cost only where drift is possible. **Asked-not-answered (#555 Phase 3):** when a yes/no scope question was asked and the operator's next message does not answer it, log the entry `asked-not-answered` — NEVER silently upgrade it to accepted — and carry it into the panel's input. **Frozen-chat degrade (#555 Phase 4):** if the session's chat history is a frozen /handover file with ZERO live operator turns since resume, skip the three-model panel and dispatch ONE over-reach/scope-completeness verifier instead; record `chat_reconciliation_mode: degraded (frozen-handover)`.
2b. **Sign-off-gate completeness (#555 Phase 3).** The pause message ITSELF must inline the full contract substance — the files-changed table, the mechanism summary, the out-of-scope list with each item class-tagged (`confirmed-FP` / `owned-elsewhere` / `scope-assertion`), and every open decision — never a bare /tmp pointer. Any decision deferred to this sign-off gate must have its dependent AC pre-written and marked `pending-confirmation`. Any OOS item parked behind a future decision gate carries a 1-2 line pre-grounding note (supervision model / blast radius) inline.
3. Layer-2 subtasks in the same Workflow (DIFFERENT prompt, per AP#14c): cross-check layer 1 findings. Specifically verify no false positives and no false negatives in scope. (Agent/Task = the documented fallback only for a trivial single-angle check.) **Layer-2 standing categories (AC 3.6/3.8/3.12):** REJECTED-FINDING-REVISIT — re-walk every finding the Stage-2 main agent rejected; confirm the rejection still holds against the current draft. Stage-2-correction audit — explicitly walk every AC modified by Stage-2 Layer-2; correction-on-correction drift is the highest-probability residual error class. For each Layer-2 subagent declare: (a) angle job spec, (b) which Layer-1 outputs it reads, (c) whether it is merged with another angle and why — record merges as `L2-merge:[angle-A+angle-B]: <justification>`.
4. Each subagent returns a RESULT block. Main agent reviews ALL results. **Before acting on any L1/L2 BLOCKING finding (AC 3.6):** (1) run the same raw query in main-agent context to source-verify the finding; (2) for wrong-identifier replacements, confirm the replacement is correct-by-intent (architecture alignment), not just correct-by-existence; (3) for FAIL verdicts touching another repo's issue closure, classify as a known over-scope class and demote to low-priority. **Cross-stage contradiction (AC 3.13):** when Stage-2 and Stage-3 subagents reach incompatible conclusions on the same factual question, the main agent reads the source file directly and cites the literal text as the resolution — NEVER resolve by recency bias (a newer subagent finding ≠ authoritative finding). **Failed-agent coverage accounting (#555 Phase 4):** a socket/transport-failed subagent's angle is recorded explicitly UNCOVERED in the RESULT tally — never silently reported as N-2 of N complete. **Mid-flight scope delta (#555 Phase 4):** if the operator adds scope while a Stage-3 swarm is in flight, record `audited_sha` (`git rev-parse HEAD` at dispatch); re-verify only the delta introduced after that SHA — reuse the completed swarm's findings for everything unchanged, never discard-and-re-audit.
5. If ANY subagent finds a gap: fix the draft. Do NOT create the issue with known gaps. **Post-corrections resync (#555 Phase 4):** after applying any batch of draft corrections — or inserting an AC that adds new files/languages/commit-units — re-read and resync in the SAME pass: (a) the SUMMARY layers end-to-end (title, Problem/Goal, EB list, illustrations); (b) the Anti-Bias file list, commit-atomicity note, and File-Housekeeping created-files list. Corrections that land in ACs while sibling sections keep stale framing are the AP #9 class. **Re-worded ACs (#555 Phase 4):** re-run every REWORDED AC's verify command against the pre-fix tree in the SAME pass as the wording change.
6. Once ALL subagents agree the draft is complete and accurate AND the operator has approved the `## Chat Reconciliation` report (step 2a): create the GitHub issue using the verified draft verbatim. **(#555 Phase 3)** For a public-repo scrub issue or voice-guarded artefact, the LAST step before `gh issue create` is the scrub — em-dash/voice violations, then `check-public-repo-secrets.py` — run AFTER the final manual edit, whatever that edit was.
7. Report the issue URL to the user.
8. **CONTEXT CHECK REMINDER**: After reporting the issue URL, tell the user their current context usage percentage and advise: "If remaining is near ~50% (≈500K of 1M used), run `/handover` + compact before invoking `/Leader 4` — Stage 4 re-invokes `/SST3-solo` which reloads STANDARDS.md + CLAUDE.md + WORKFLOW.md + the Issue, so a compact here loses nothing and gives maximum room for implementation."

**DO**: Investigate when subagents disagree. Fix gaps before creating the issue. Verify against chat history. Remind user about context before Stage 4.
**DON'T**: Rubber-stamp. Pick the convenient answer when subagents conflict. Put scope in comments.
