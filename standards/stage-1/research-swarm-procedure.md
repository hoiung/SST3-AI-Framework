## Procedure

Scale subagent count to match scope. No maximum. No minimum of 2-3. If 12 directories to check, dispatch 12+ subagents. Every subagent covers a different angle, directory, file set, or data source. No two subagents share the same prompt.

**Process**:
0. **Restate the task in the user's exact words** at the TOP of the research file, before any other content. Quote the user's original phrasing verbatim. If your interpretation requires translating jargon, preserve the original alongside your interpretation. Rationale: an intent error cannot be caught by any graph query or subagent angle — only pre-swarm restatement can. Stage 3 sanity-check verifies the restatement matches the user's literal task before approving scope. **Named-entity fidelity (AC 3.1):** any specific entities, values, or sets the operator enumerates (e.g. `MB100/MBS100`, a named file list, specific tickers/IDs) are preserved VERBATIM in the restatement; NEVER broaden a named SET to "all" / "uniform" / "every" / "any" as a simplification — the enumeration IS the scope (the inverse of AP #14e; canonical rule: STANDARDS.md "Named-Entity Scope — Don't Broaden a Named Set").
0a. **Identify invoked skill + record skill-canonical metadata** (N32 Double-Guardrail first link). Record in the research file: `invoked_skill: <skill-name-or-"none">` and `skill_canonical_files: [list of files]`. Examples — `blog` / `voice-doc-repo` → `dotfiles/.claude/skills/voice/SKILL.md` (the loader; it owns the guard floor, and omitting it curator-bounds the comprehensive walk that reads this metadata — neither file below carries the Cite-or-cut floor check), `voice_rules.py`, `voice-doc-repo/VOICE_PROFILE.md`; `ebay-seller-tool` → Seagate HARD CONTRACT + 21-field listing contract docs; `claude-api` → prompt-caching SDK references + current model IDs; `SST3-solo` / `Leader` → N/A (cross-cutting SST3 only, no domain skill). If task is pure infrastructure (no domain skill invoked), record `invoked_skill: none`. This metadata is READ by Stage 3 (skill-canonical compliance subagent angle), Stage 4 Gate 1 (skill-canonical verification checkbox), and Stage 5 (skill-canonical audit). See STANDARDS.md "Double-Guardrail Principle". **Primary driver-repo selection (AC 3.9):** which repo owns the active skill canonical? `dotfiles` is reserved for SST3-framework issues, not domain work that merely uses SST3 — file domain work in the consumer repo that owns the canonical.
0b. **Prior-feedback ground** (per STANDARDS.md §Per-Stage Feedback Capture): read aggregator output via `bash $SST3/leader-feedback-aggregate.sh --report` (markdown — pull "Pending Improvements" + "Top 5 Improvements per Stage" sections). For topic-keyword overlap, run `bash $SST3/leader-feedback-aggregate.sh --shape-match <kw1>,<kw2>` and pull top 1-3 referenced feedback files. Pull `improvement` field where `improvement_status: pending` into the Stage 1 /tmp scope file as 'patterns to apply / pitfalls to avoid'. When a prior `pending` improvement is satisfied by this run, close the loop with `bash $SST3/mark-improvements-applied.sh` (the canonical tool — it sets `improvement_status: applied` AND writes a STANDALONE `**applied_in**: <this-issue>` field line). The `applied_in` marker is ALWAYS its OWN field line — NEVER hand-cram `applied_in: ...` inside the `improvement_status` value (that produces a non-enum value the feedback parser rejects with exit 1, and the file then sits un-aggregatable until fixed). Token budget ~12K total (report ~3K + at most 3 prior feedback files at ~3K each). Skip-cleanly when index empty (mechanism not yet activated, or first issue post-activation).
0c. **Chat Reconciliation — Agreements Log + early verifier pass (AC 6.1; doctrine: STANDARDS.md "Chat Reconciliation (Verifier-Led)").** Maintain a `## Agreements Log` section in the research file: extract the operator's raw typed messages with `python3 $SST3/extract-chat-agreements.py --issue <N>` and append an agreement bullet (with its transcript ref) AS each agreement is made (captured-when-agreed, not reconstructed-late; do NOT duplicate the verbatim restatement from step 0 — link it). Then run ONE neutral independent-verifier pass (the cheapest/earliest drift catch): dispatch a fresh-context subagent given ONLY the extracted messages + agreements log (it is NOT shown your proposed scope) and the neutral prompt "from these messages, what did the operator ask for / agree to / rule out?", and double-check its independent interpretation against your proposed research scope — flag `invented` / `dropped` / `inverted` divergence before the swarm. (The full THREE-MODEL Haiku+Sonnet+Opus panel + operator sign-off run at Stage 3 step 2a and Stage 5; Stage 1 is a single early pass.) The `--issue <N>` flag (dotfiles#528 AC 5.3) selects THIS issue's worktree session transcript by slug — required because a bare-parent (canonical-clone) project dir accumulates many issues' sessions; without it the tool now FAILS LOUD on that ambiguity rather than silently picking latest-by-mtime (which could be another issue's session). Resolution hardened (#555 Phase 3): `--issue N` also resolves bare `wt-N` worktree slugs; the CWD-derived slug uses Claude Code's real every-non-alphanumeric→`-` scheme (underscore/dot/plus paths); a directory-format session layout falls back to nested main transcripts (subagent/tool-result sidecars excluded, all chunks of the latest session oldest-first); and a no-transcript dir fails loud printing the exact `--session` workaround. Untrusted-output fallback (#555 Phase 4): if the extractor's output is empty, errors, or reads content unrelated to this Issue, treat it as UNTRUSTED — hand-capture the operator's verbatim messages into the `## Agreements Log` directly; pre-issue-creation (no transcript, no Issue yet), the operator handover/brief is the agreement source.
1. Check `docs/research/` in the active repo for existing research FIRST. Do not re-derive what exists. **Non-code-framing live probe (AC 1.9)**: for any scope framing that asserts a non-code or operator-side classification ("not a code issue", "operator-side state", "false positive on contract X", or a code-grep concluding a flag is "never set"), dispatch ONE verifier subagent that probes the live system (grep dynamic construction patterns: `f"{...}_<suffix>"`, `setattr`, dict-key f-strings; DB/log probe) BEFORE accepting the framing. A live DB row exhibiting the flag is authoritative over any "never set" code-grep result. Guard-liveness expansion (#555 Phase 4): a fail-open / never-fires / connection-ownership / 'backend X serves this UI' claim is a hypothesis until ONE live invocation through the real harness runs — paste the full signature of every function on the asserted call path (a `git log -S` miss is non-evidence) and trace frontend fetch-URL → router → actual serving entrypoint, never filename priming. Evidence-channel corollary: the RESULT `evidence_command` must be the actual grep/invocation that RAN — never a subagent's assertion relayed as evidence (binds the AC 1.6 RESULT-block contract to this angle). Trace-to-endpoint at research time (#555 Ralph r3): for any 'X produces Y' claim, read the call chain to the ACTUAL emitting statement before fixing a locus; a NEW payload field/code surface proposed as a decision gate is traced to its user-visible consumer — none found ⇒ fold into mechanism, not a scope choice.

1a.5. **PRE-SWARM SOURCE-VERIFICATION GATE for handover claims** (Theme 1, #477): if a pre-research handover or post-compact recovery summary exists at session entry, main agent MUST extract 3-5 headline claims (file:lines, counts, table sizes, "X doesn't exist" assertions, named functions / hooks / scripts said to exist) from the handover and verify each via raw-grep / Query / direct read BEFORE dispatching the swarm. Document any drift in the /tmp research file as "claim X corrected from Y to Z before swarm dispatch". Memory ≠ source of truth; handover ≠ frozen contract. Rationale: pre-swarm verification catches scope-amendment cycles that would otherwise force mid-Stage-2 AC rewrites or a Stage-4 false-positive bug-hunt. Cross-reference: STANDARDS.md "Never Assume — Always Check" → "User Assertion = Immediate Source Verification" sub-rule, Rule 1b ("Handover claim → grep source immediately"); ANTI-PATTERNS.md AP #14d (Scope-gap blindness — Stage 1 research specific). **Three explicit verification classes (AC 1.7):** (1) **Closure-rationale claims** — grep each architecture claim (e.g. "X mechanism handles Z") before accepting scope; (2) **Pre-existing classification** — fetch the cited Issue body + commit list and verify scope overlap before accepting "pre-existing #N" framing; (3) **Fix ranking** — the Layer-2 adversarial prompt (step 2a) MUST include a named sub-angle: challenge the handover's fix ORDERING against source, not just factual accuracy. If the handover's core hypothesis is mechanically testable (exit code, guard presence, scanner output), run the ONE decisive command BEFORE writing the Issue contract and record the result in the /tmp research file §0.5. (4) **Behavioral premises (#555 Phase 4)** — any handover claim describing HOW a mechanism behaves (not only that it exists) is source-verified (read the implementation, or run it) before folding into frozen scope, with the same rigor as an existence/file:line claim.
1b. **Pre-swarm wrapper-lane SEED**: if the research topic is structural code in a supported language (see STANDARDS.md "Structural Code Queries"), use the wrapper-lane to DEFINE scope BEFORE dispatching the swarm — not to verify pre-formed scope AFTER. Run `bash $SST3/sst3-code-callers.sh <symbol> <lang>` / `bash $SST3/sst3-code-callees.sh <function_name> <lang>` / `bash $SST3/sst3-code-search.sh '<pattern>' <lang>` on every symbol the USER MENTIONED, plus `bash $SST3/sst3-code-impact.sh <base-branch>` on user-named files. Feed the resulting call-site / symbol / blast-radius data into subagent prompts so layer-1 angles are scoped to real evidence, not hypothesis. Wrapper-lane findings SEED the swarm; they do NOT replace its different-angle coverage. **Hybrid topics** (code + docs): run wrapper-lane queries on the code portion ONLY; use subagents for the semantic portion. Record `graph_applicable_files` vs `graph_exempt_files` in the research file. Skip-condition: if topic is semantic / voice / intent / cross-document / non-code (12 subagent-only moments per STANDARDS.md), skip wrapper-lane queries and go to step 2 — the 1a status CHECK still ran unconditionally for audit trail. Record wrapper-lane calls + `last_updated` + `file_count` + one spot-check file:line per query in the /tmp research file. (`search` is keyword-only — there are no embeddings; verify with synonym sweep before any "no match" conclusion.) **Cross-validation rule (#447 Phase 5 — wrapper-lane vs raw recall delta gate)**: BEFORE dispatching the swarm, cross-validate the wrapper-lane SEED against ONE raw-tool subagent on the same query (e.g. wrapper `sst3-code-callers.sh foo python` vs subagent grep `^def foo|foo(`). Compare counts. Delta ≤20%: trust the SEED, dispatch the planned swarm. Delta >20%: wrapper-lane is SUSPECT for this query class — dispatch matched wrapper+raw subagent pairs for layer 1 (one subagent per pair) so the swarm covers both signals; record the delta + final reconciliation in the research file. The 20% threshold is empirical (#445 R4 wrappers landed at 0% delta against raw on structural angles; pre-R4 sat at 17% large-fn recall which is why a 20% bound surfaces drift early). **Empty-SEED fallback trigger (AC 1.11):** if the SEED result is empty for a symbol the task description asserts exists, immediately run `grep -rln <symbol>` as a raw cross-check. If the delta between SEED count and raw grep count is >20%, use the raw call-site map to scope subagent angles (the wrapper is unavailable for this query class). Record `pre_swarm_graph_seed: skipped (reason: <wrapper-unavailable|empty-delta>)` in the /tmp research file §0 frontmatter. Note: Rust + async + multi-file symbol topics default to skip-clean on the SEED; record the reason explicitly. Method-symbol default (#555 Phase 4): for controller/class-method Python symbols, default the SEED straight to raw-grep call-site mapping — do not first attempt the wrapper call known to return empty for method-style symbols; record `pre_swarm_graph_seed: skipped (reason: method-style-symbol-class)`.
1.5. **Live-environment baseline (AC 1.9):** for tasks on a specific host or deployment, capture a live-environment baseline (`lscpu`, `free -h`, `df -h`, service status, AppX/scheduled-task state) into `/tmp/host-baseline.txt` and pass its path to every subagent angle as context. Static analysis of a host-specific task without a captured baseline is an unverified framing.

Large-corpus reads (#555 Phase 4): for line-by-line corpus reads with a required output schema, cap clusters at ≤3-4 large files per subagent OR restate the StructuredOutput requirement at the END of the prompt — instruction-following degrades over a long single-turn read. Shared-context premise verification (#555 Phase 4): before stating a component's data-source wiring in a swarm prompt, grep importers (`grep -rln <hook>`) — a wrong premise in the SHARED context propagates to every agent that does not re-derive it. BEFORE any drafting begins — never auto-split on subsystem/architecture grounds.

Synthesis subtasks MUST be dispatched AFTER all swarm outputs are on disk — the synthesis subtask prompt must name the input files it reads, and those files must exist before the subtask runs. Seam ownership (#555 Phase 4): when the topic spans a shared seam between two subsystems/angles, name ONE angle as the seam's explicit owner — a seam left to both sides generically is deferred by both and dropped. Content-tree partitioning (#555 Phase 4): enumerate mechanically via `git ls-files | awk` over every section AND leaf path — never an assumed structure — and assign each resulting subpath a named owner angle before dispatch.

For changes that fan out to consumers, query `SST3/drift-manifest.json` `mirrors` array for the per-file consumer count rather than asserting a uniform N. For install/bootstrap topics, enumerate all entry points (`install.sh`, `provision.sh`, `*.ps1` equivalents) BEFORE proposing new install steps. 2a. **Layer-2 adversarial gap-finder MANDATORY for Stage 1 swarms** (Theme 8, #477; AP #14 instantiation): after the Layer-1 swarm completes, include a Layer-2 adversarial gap-finder subtask in the authored Workflow (run after the Layer-1 subtasks; Agent/Task = trivial-single-angle fallback) with the explicit prompt: "Layer-1 found X, Y, Z. Find 3 things they missed — either (a) false-positive claims that are already covered by modern equivalents (e.g. legacy registry key vs Win11 24H2 modern equivalent; SetUserFTA legacy API vs UserChoice ProgId modern path), or (b) genuine gaps not yet surfaced (scope adjacent to Layer-1 angles but uncovered)." For infrastructure / governance / cross-cutting Issues this angle is load-bearing — Layer-1 generic-angle coverage misses scope-adjacent gaps that Layer-2 different-prompt sweeps catch. Layer-2 prompt MUST differ from Layer-1 (per AP #14c — different angle, different blind spots). **Sub-question splitting (#555 Phase 3):** split each named structural angle into its own ONE-LINE sub-question with the instruction "answer ALL N; leave NOT_RUN visible for any unanswered one" — or run the gap-finder on a higher model tier; an unanswered named sub-question is a degenerate result (step 4a's auto-re-dispatch applies), not a pass. Cross-reference: STANDARDS.md "Stage 1 Layer-2 Adversarial Gap-Finder Discipline" + ANTI-PATTERNS.md AP #14d. **Required structural angles (AC 1.8)** — the Layer-2 prompt MUST include these 8 named angles when applicable: (1) **hot/cold path enumeration** — for each data-consumption site enumerate (a) cold-path validation, (b) hot-path validation, (c) revalidation interval; flag any path with (a) lacking (b); (2) **async/sync compatibility** — for any recommended reuse target, verify the async/sync context matches the call site; (3) **operator-semantics grep** — verify `>=`/`>`/`<=`/`<` in threshold claims against source code, not prose; (4) **tool-disambiguation** — when the operator names a specific product/tool, one angle must verify exact feature identity against official docs; (5) **self-disconfirmation** — list 2-3 simplest scenarios under which the alleged gap does NOT exist; verify each against source; (6) **Sibling-pattern enumeration (AP #14e — Issue #54)** — for any finding about a function, pattern class, or family member, enumerate ALL callers / branches / sibling files that could share the same defect class before returning a verdict: extract the CONCEPT and use concept-based grep, not literal-pattern grep. The literal-pattern sweep finds only what already shares your vocabulary, so a family member named differently survives the sweep untouched — which is exactly how Issue #52 shipped a miss that Stage 5, where this instruction WAS wired, then caught. Mirrors the Stage-5 **Sibling-pattern enumeration (AC 5.3)** angle; the two are deliberate twins — edit both or neither; (7) **Source-as-consumer enumeration (AP #30 — Issue #54)** — when a producer and its consumer share no token, the producer is itself a candidate consumer. Enumerate paired surfaces by asking "what else emits or consumes this fact?", never by grepping the producer's own name; a token-blind pair escapes both the AP #24 literal-marker grep and the AP #14e pattern-class sweep. Mirrors the Stage-3 **Producer-surface enumeration** angle below, which fires too late to scope Stage-1 research.; (8) **canonical-assumption challenge (#555 Phase 4 — Issue #1-s5 ord2)** — read the active repo's CLAUDE.md cover-to-cover; flag the most load-bearing architectural claim adopted as a starting truth without recent operator confirmation. Early seeding for named domains (#555 Phase 4): for voice/positioning-repositioning and niche-audience-platform topics, seed the adversarial/brand-coherence gap-finder INTO Layer 1 from the start — a gap discovered only at Layer 2 has already let a generic Layer-1 angle anchor the scope.
3. Main context = orchestrator ONLY. Do NOT read source files directly. Subagents read; main agent collates.
4. If subagents return uncertain or conflicting findings, dispatch MORE subagents to resolve. Do not guess. **When Layer-2 surfaces false-positive corrections to Layer-1 claims** (e.g. Layer-2 says "Layer-1 cited legacy API X, but modern equivalent Y exists in Win11 24H2"): main agent must verify the equivalence against source BEFORE accepting the correction; document the verification method inline (command run, file:line, URL). Both Layer-1 and Layer-2 outputs are subagent recommendations; the source decides (per AP #14c). Pattern (#477 Theme 8): main agent dispatches a verification subagent with the prompt: "Run `grep / ls / Query` against <file>:<line> to confirm whether <legacy claim> or <modern equivalent> is present in the actual codebase. Report file:line + verbatim quote." Drift between Layer-1, Layer-2, and source = block scope-acceptance until reconciled.
4a. **Degenerate-RESULT detection + auto-re-dispatch (#555 Phase 3):** post-swarm, BEFORE collation, scan every subagent reply for a degenerate result: a missing `## RESULT` fence, a body below a sane length floor (~200 chars), or a mandated named sub-question left unanswered with no visible `NOT_RUN`. Any hit = auto-re-dispatch THAT single angle (same prompt, or one model tier up) — never collate around the hole and never rely on manual eyeballing to notice it. Digest fidelity (#555 Phase 4): build any L2/completeness-critic digest from the HEAD of each RESULT block (verdict + coverage_note + files_touched), never a tail-slice — a tail-sliced digest manufactures false 'unowned cluster' claims.
5. Collate ALL findings into `/tmp/research_<topic>_<date>.md`. File MUST contain:
   - **Findings** — each backed by file path, line number, command output, or URL
   - **Gaps identified** — what the research did NOT cover or could not confirm
   - **Plan / ideas / angles / idea-repo** — based on facts and data, not opinions or assumptions. Brainstorm with subagents to generate new angles, then verify each angle against evidence before including it.
   - **References** — every claim has a provenance trail (file:line, command output, URL, calculation showing how numbers were derived)
   - **Truth-table temporal axis (AC 5.5)** — for any truth table in an AC, add a Temporal axis row (mid-flight | terminal) and enumerate all parameter modes (`full_history=True/False`, etc.). A truth table that omits the mid-flight-vs-terminal axis silently assumes terminal-only and misses the in-progress state class.
6. Present summary to user with `/tmp` file path. **Stage-1-close validator (#555 Phase 3):** run `python3 $SST3/check-stage1-research-fields.py <research-file>` and require exit 0 BEFORE Stage-1 sign-off — do not defer the first run to Stage-2 entry, so a fresh/post-compact Stage-2 session never opens onto a validator failure. The Stage-2-entry run stays as a redundant re-check, not the sole gate. **Pre-filing hypothesis run (AC 1.3):** Before writing the Issue contract, run any mechanically testable hypothesis (exit code, guard presence, scanner self-test) that would collapse the scope — record the result in §0.5 of the research file. **Live-consumer gate (AC 1.5):** For each proposed AC, identify the live consumer — who reads this output, and what do they do with it? If no live consumer, exclude from scope.

**DO**: Back every claim with evidence. Dispatch more subagents when uncertain. Check existing research first. Brainstorm new angles with subagents. Verify every idea-repoed idea against evidence before including it. Record `graph_applicable: true|false (reason: <class>)` in the /tmp research file — downstream stages 2/3/4/5 MUST read this field and do NOT re-derive the classification independently (single-declaration-carries-forward, TB-2 N29+N34).
**DON'T**: Read source files in main context. Default to 2-3 subagents. State findings without file:line references. Hallucinate. Trust memory without verifying against source. State numbers without showing how they were calculated. Never (#555 Phase 4): conclude absence from head-N output — re-run unfiltered with an explicit count; cite a file:line anchor without ls/`grep -rln` confirming the actual subdir; quote a log line in a scope snippet without grepping its emitter across scripts/ AND src/ and NAMING the emitting file.
